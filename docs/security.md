# Security

Never commit passwords, API tokens, private keys, webhook secrets, database credentials, or production connection strings.

Use least-privilege service accounts, TLS verification, scoped API access, credential rotation, structured redaction-aware logging, and explicit separation of read/write identities where feasible. Treat location/personnel context according to local privacy, HR, legal, and records-retention requirements.

Security concerns should be reported privately to the project maintainer rather than disclosed in a public issue when exploitation or sensitive data may be involved.
